# FN软仓 完全指南（整合版）

> 本文由《FN软仓服务端使用指南》与《三方源加入及开发者系统申请指南》整合而成，按「认识项目 → 部署服务端 → 上架应用 → 客户端接入 → 进阶配置 → 多人协作 → 聚合申请 → 零成本替代方案 → 故障排查」的顺序编排。

---

## 一、认识项目：服务端与客户端

FN软仓项目包含 Docker 服务端和 fpk 客户端两部分：

- **服务端（fn-appstores-server）**：专为飞牛 fnOS 打造的第三方应用商店后端。具有公告与轮播图管理、应用上传、应用编辑/管理、应用及设备信息统计、三方源聚合管理、IP 限速、fpk 的 GitHub 直链加速、开发者系统、消息推送等功能。支持**全托管模式**作为 fpk 应用分发平台，也支持**半托管模式**为客户端提供 fpk 下载链接。最大优点：任何人拿到 Docker 镜像，就可以另起炉灶构建个人专属的 fpk 应用分发平台。
- **客户端**：具有公告和轮播图接收、应用列表显示、应用安装/卸载/更新/修复/配置备份与恢复、应用评分、应用收藏、开发者星球、主题跟随与设置、客户端新版本检测等功能。

搭建三方源，本质上就是搭建一个供客户端访问的**「源地址」**。有两条路线可选：

- **路线 A：Docker 服务端**（本文第二～六章）——功能完整，推荐
- **路线 B：纯静态源**（本文第七章）——零成本、零运维

---

## 二、部署服务端（Docker）

**适用人群**：拥有 VPS 或公网 IP 的玩家，或直接把 Docker 跑在飞牛 NAS 上的极客。
**核心优势**：完整的网页管理后台、防刷限速、数据统计以及开发者入驻审核系统。

### 1. 编写 docker-compose.yml 并启动或直接安装**FN软仓服务端fpk**  

新建 `docker-compose.yml`，然后执行 `docker compose up -d`：

```yaml
version: '3'
services:
  app:
    image: ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.10.0
    container_name: fn-appstores-server-go
    restart: unless-stopped
    ports:
      - "[::]:5660:5660"
    volumes:
      - ./data:/app/data
    environment:
      - TZ=Asia/Shanghai
      - BASE_URL=http://你的IP或域名:5660
      - ADMIN_PASSWORD=你的后台密码
      - AUTO_CLEAN_DEV_UPSTREAM=   #值为1则启动上游开发者源失效自动清理，0或留空则默认关闭
      - TRUST_PROXY=   #直连公网（没有反代，直接访问 服务器IP:端口）时填false，反之填1。 
```

### 2. 登录后台管理系统

- **访问地址**：`http://你的NAS_IP:5660/admin`
- **管理员账号**：`admin`
- **管理员密码**：安装时在向导中填写的 `ADMIN_PASSWORD`（默认 `admin`）

> ⚠️ 如果页面打不开，请检查飞牛防火墙是否放行了 `5660` 端口，或在飞牛 Docker 容器列表中查看端口映射情况。

## 三、上架应用：选择托管模式

服务端分为 **全托管** 与 **半托管** 两种模式，先选模式再上传。

### A. 全托管模式

- **操作**：在后台「应用管理 → 应用列表 → 上传应用」拖入 `.fpk`，保持「托管 FPK」和「托管图标」**全部勾选**。系统会自动解析 FPK 包内的应用图标、名称、版本号和简介。
- **逻辑**：服务端包揽 JSON、图标、FPK 文件的所有存储和分发。
- **优缺点**：极度省心，但**极度消耗服务器带宽**。家庭 NAS（上行带宽极低）用户下载一个 100MB 的应用会把宽带瞬间打满，体验极差。**仅推荐公网高带宽服务器使用**。
- 上传完成后，确保将应用状态设置为 **「上架」/「公开」**。

### B. 半托管模式（强烈推荐）

- **操作**：上传 `.fpk` 时**取消勾选「托管 FPK 到服务端」**（FPK 和图标都走外链时，图标托管也取消），填入 GitHub/Gitee 等**外链直链地址**（注意必须填直链）。
- **逻辑**：服务端只做「导购员」——用户下载时服务端返回 `302` 跳转，让用户的 NAS 直接去 GitHub 下载大文件。
- **带宽消耗真相**：服务端依然会消耗一点带宽下发 JSON 和图标（约 20KB–50KB/个），但流量极小，1Mbps 小水管也能 2 秒加载完一屏；**几十上百兆的 FPK 下载流量完全绕过你的服务器**。
- **神级实战**：无公网 IP 的家庭 NAS 玩家，可配合 52frp 的低价穿透节点——穿透节点只传微小的 JSON 和图标，毫不卡顿；大文件下载直接走 GitHub，完美避开家宽和穿透流量的双重瓶颈。

## 四、客户端接入

这是客户端能连上你商店的关键步骤：

1. 复制服务端的 **BASE_URL** 备用（即 `http://你的IP或域名:5660`）。
2. 安装 FN软仓客户端（**2.10.0 及以上**版本，建议 2.11.0 及以上），选择「极客模式」。
3. 打开客户端，进入 **「源管理」→「添加第三方源」**，将 BASE_URL 粘贴进去。
4. 保存并刷新客户端。后台里上架的应用就会出现在客户端列表中。
5. 点击下载，即可直接从你的 NAS 拉取应用包并一键安装。

## 五、进阶配置

### 1. 修改 BASE_URL

更换域名或穿透地址后，在飞牛 Docker 管理器中修改容器的 `BASE_URL` 环境变量（如 `http://新的IP:5660`），然后重启容器。

### 2. 公告管理

登录后台后可发布系统公告，客户端会推送给所有连接此源的设备。

### 3. 轮播图（2.10.0 及以上服务端支持跳转）

进入后台配置轮播图地址，三种跳转写法：

- 跳转外部链接：`图片URL|url:https://xxxx.xxxx.com`
- 跳转应用详情：`图片URL|app:appid`
- 跳转应用分类标签：`图片URL|tab:settings`

### 4. 数据备份

所有数据库文件都保存在飞牛的 `@appdata/` 安全区，升级或重装应用不会丢失配置。

### 5. 加速站配置

请自行添加加速前缀。

## 六、开发者系统（多人协作）

> 开发者系统的所有核心逻辑都在「服务端」，客户端完全无感知。

搭建好 Docker 服务端后，你不仅是源主，还拥有一个「应用提交审核平台」，可以邀请其他开发者入驻，实现多人协作。

### 协作流程

1. **开发者申请**：把你的 `http://你的域名:5660/dev/apply` 发给其他开发者，对方在网页填写入驻信息。
2. **源主发号**：在后台「开发者管理」点击通过，系统生成一个带 `token` 的专属后台链接，发给对方。
3. **开发者提交**：开发者在他的后台页面拖入 `.fpk`，填入 GitHub 外链，点击保存。
4. **源主终审**：在后台「审核中心」点击通过，服务端自动把该应用写入 JSON 并上线。
5. **客户端展示**：用户刷新软仓客户端，拉取你服务端的 `/api/apps` 接口即可看到该开发者的应用——用户完全不需要知道这是哪个开发者传的。

> 💡 穿透环境提示：即使服务端跑在低价内网穿透上，开发者系统依然能完美运行——在线填表、拖入解析、点击审核，全程只是几十 KB 的文本传输。

## 七、聚合申请（加入大源，获得曝光）

辛辛苦苦搭好独立服务端后，怎么让海量用户**不手动添加你的源**也能在官方源里直接看到你的应用？答案是「树状聚合」。

### A. Docker 服务端的聚合申请

- **玩法**：提交你的**服务端地址**（如 `http://你的IP:5660`）进行聚合申请；也可以向其他跑 FN软仓服务端的三方源申请聚合。
- **入口**：FN软仓客户端「设置」里有官方源聚合申请通道。
- **效果**：官方源或三方源源主审核通过后，你的服务端会作为「三方源」接入其后台。用户打开软仓，哪怕没添加你的源，也能刷到你提供的应用，获得巨大曝光。
- **⚠️ 注意**：不建议彼此聚合（A 聚合 B、B 又聚合 A），也不建议超过 2 重聚合（A→B→C→D……）。

### B. 纯静态源的聚合申请

纯静态源一样可以申请聚合：在官方社区的**聚合申请表单**中，填入你 `fnrc.json` 的 **Gitee 直链**（如 `https://gitee.com/xx/yy/raw/master/fnrc.json`）。官方服务端会自动解析 JSON，把你的应用无缝合并到官方列表中。

## 八、路线 B：纯静态玩法（零成本、无服务器）

**适用人群**：只有几个自己开发的应用，不想碰 Docker，只想白嫖代码托管平台。
**核心优势**：零成本、零运维。

### 操作步骤

1. 把 `.fpk` 文件上传到 GitHub Releases，获取直链。
2. 编写 `fnrc.json`，把直链填入 `download_url`（可通过 FN软仓助手的 fpk 编辑功能生成）。
3. 把 `fnrc.json` 托管到**国内可直连的静态空间**（必须放 Gitee）。

### ⚠️ 致命避坑警告

- **千万不要把 `fnrc.json` 放在 GitHub 上！** 客户端请求该文件时不走加速，国内极易因 `raw.githubusercontent.com` 被 DNS 污染导致拉取失败。**必须放 Gitee**。
- **`.fpk` 文件可以放心放 GitHub**：客户端下载 FPK 时会自动走内置的外链加速器。

### 示例 fnrc.json

```json
{
  "source_name": "我的静态源",
  "apps": [
    {
      "id": "myapp",
      "name": "测试应用",
      "version": "1.0.0",
      "download_url": "https://github.com/xxx/releases/download/v1.0.0/app.fpk",
      "platform": "x86"
    }
  ]
}
```

## 九、故障排查

- **后台打不开**：检查飞牛防火墙是否放行 `5660` 端口；检查 Docker 容器端口映射。
- **查看服务端日志**：`sudo docker logs -f fn-appstores-server`（飞牛上容器名以实际为准，如 `fn-appstores-server-go`）。
- **仍有问题**：前往 FN软仓相关社区提交 Issue。
