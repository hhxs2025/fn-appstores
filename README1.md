# FN软仓服务端-使用说明
## 项目说明
FN软仓是专为FNOS(飞牛nas)设计的一个**三方应用商店搭建工具**。
**包含**：**服务端**[docker]和 **客户端**[fpk]两个部分。
## 服务端:[最新版2.12.0]
### 核心功能：
|   核心功能项 |  说明  |
| :--------: | --- |
| 公告管理 | 1.轮播图管理【支持跳转到应用详情、外部链接、应用分类标签页】；2.公告管理；【支持优先级排序】 |
| 源管理 | 1.支持聚合跑FN软仓服务端搭建的三方源的地址；2.支持聚合fnrc.json源地址 |
| 应用明细 | 1.服务端本地源下应用的架构、类型、版本及json预览，应用名和id搜索；2.三方源应用的架构、类型、版本查看及按源筛查，应用名和id搜索；3.服务端配置文件(服务端data/目录下json和db文件)备份与恢复、孤儿文件清理。 |
| 应用编辑 | 1.应用名称/版本/作者/类型/架构/描述/直链/预览图等信息编辑；2.应用新增,应用架构批量修改设置；3.应用删除、应用名称和id搜索。 |
| 应用上传 | 1.拖入fpk自动解析元数据并写入到服务端fn-appstores.json，同时支持自动提取ICON和重命名fpk并存储到服务端目录【全托管模式/分发平台模式】；2.支持fpk和icon走外部直链，以减轻服务端所在服务器压力；【半托管模式】；3.应用截图管理：支持服务端托管或走外部直链； |
| 仪表盘 | 1.应用总数、不同架构应用数、源类型/数量及不同源下应用数统计；2.下载概览、设备统计；3.近30日下载趋势、今日/本周下载量TOP10；3.设备统计及类型分布；4.下载明细及下载数据导出csv |
| 消息推送 | 1.邮件通知：支持QQ、163、Gmail、阿里/腾讯企业邮箱、自建邮箱；2.webhookt通知：支持钉钉/企业微信/飞书/自定义；3.通知事件涵盖：开发者申请、开发者应用待审、三方源状态变化、应用上架/下架/更新、每周运营周报；4.定向消息推送：支持全量、按架构、按客户端版本、按客户端ID推送，推送消息形式支持轻提示、强弹窗、强制更新 |
| 安全管理 | 1.下载限速与IP封禁【仅对全托管分发平台模式下fpk下载请求有效】；2.设备明细与封禁、设备状态查看【需配合服务端环境变量设置,fpk版docker服务端已默认配置好了】
| 外链加速 | 针对【半托管模式】玩法下走Github直链的fpk下载进行加速，需自己配置；支持加速站健康检测定时设置和动态测速排序；|
| 开发者管理 | 1.新增开发者系统子源；2.开发者后台支持webhook配置,便于开发者及时接收应用上架/更新的审核结果；3.支持fpk拖入后自动解析元数据并写入开发者子源json，支持自动从fpk提取ICON托管到服务端,fpk只支持外链；4.应用更新审核后mainifest字段对比表查看；5.未审核超时提醒、审核记录清理。 |

### 使用方法：

#### 玩法一：自建服务端
1.安装FN软仓服务端fpk（docker版），搭建自己的应用商店。

2.安装时需设置:【**服务端外部访问地址**】(公网地址可以是穿透或反代的ip或者域名) ，【服务端后台管理密码】(默认密码admin123)。
![服务端安装配置](https://f.hhxs2026.top:8888/f/imgs/fnrc-server1.webp)

3.应用添加：拖入上传应用根据实际确定是否勾选【**托管fpk到服务端**】和【**托管ICON到服务端**】(若有服务器或飞牛上行带宽有压力，建议不要勾选【**托管fpk到服务端**】，fpk改走外部直链)

4.若选择走【**半托管模式**】，则在上传fpk,自动写入json后，进入【应用编辑】检查表单信息，填入“下载地址”(fpk直链) [建议优选选国内Git类平台，如Gitcode或Gitee等，如填Github直链，需配置加速站]

5.轮播图：（1）轮播图存到服务端data/previews/lunbotu/下，则轮播图地址填法如下：http://xxx.yyy.com:5660/previews/lunbotu/xxx.webp      
[图片推荐webp格式]

若需从轮播图跳转外部界面，则填法如下：
http://xxx.yyy.com:5660/previews/lunbotu/xxx.webp|url:https:yyy.zzz.com

若需从轮播图跳转应用详情，则填法如下：
http://xxx.yyy.com:5660/previews/lunbotu/xxx.webp|app:应用id

**注意**：
1.若需搭建**完全独立的个人应用商店**，在服务端准备好后，安装FN软仓客户端，**首次**安装进入时选择**极客模式**，然后在**FN软仓客户端-源管理**下填入http://xxx.yyy.com:5660，从服务端后台**刷新应用缓存**，然后在**客户端-应用**里点击**刷新**。

2.若**不搭建完全独立的个人应用商店**，在服务端准备好后，可将http://xxx.yyy.com:5660发给FN软仓官方主源管理员，**申请聚合**，则用户打开软仓客户端即可看到自己的应用。

3.轮播图地址也可以填外部的图片直链，**轮播图尺寸**建议：**880x405px**。

#### 玩法二：外部json型玩法
1.从FN软仓客户端安装**FN软仓助手fpk**或从FN软仓交流群下载**FN软仓助手exe**

2.拖入fpk应用到FN软仓助手里，自动读取元数据，写json，手动填入fpk直链、图标直链等，点击“下载”导出fnrc.json，存放到能生成直链的平台(如:Gitee/OSS等)或FNOS的应用里(如:file-vault、轻量应用存储等)

3.将fnrc.json告知FN软仓服务端管理员，申请聚合。
![FN软仓助手](https://f.hhxs2026.top:8888/f/imgs/fnrc-zhushou.webp)

#### 玩法三：服务端开发者系统子源玩法
1.从FN软仓服务端管理员处获取开发者申请地址(http://xxx.yyy.com:5660/dev/apply)
2.填写源名称、作者名、联系方式，提交。
3.FN软仓服务端管理员审核通过后，通过从管理员处获得的后台地址进入后台，上传fpk读取和写入应用信息到服务端内部，手动填写fpk直链，**保存**，提交，等待审核。【也可以在后台配置webhook，便于接收应用上架、更新的审核结果通知】
